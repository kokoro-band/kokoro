# 브라우저 WebGPU 배치 요청 검증

## 사용 범위

로컬 데모의 배치 화면에서 `AI 배치`를 열고 `이 기기에서 AI 실행`을 선택하면 브라우저가 [Qwen3 0.6B ONNX](https://huggingface.co/onnx-community/Qwen3-0.6B-ONNX)를 받습니다. [Transformers.js](https://huggingface.co/docs/transformers.js)를 통해 WebGPU에서 문장을 해석합니다. 처음 받는 `q4f16` 모델 파일은 약 570MB입니다. 사용자의 배치 요청은 모델 서버에 보내지 않습니다.

모델은 한 번에 한 가지 가구 변경만 제안합니다. 브라우저가 모델의 응답을 카탈로그와 현재 가구에 대조합니다. 문장에 나온 대상과 기준 가구가 분명하면 그 항목으로 고정합니다. 공간의 문이나 가구와 겹치는 제안은 거절합니다. 제안은 확인 창을 거쳐야 브라우저 저장소에 기록됩니다. 서버 모드에서는 기존 명령 API를 사용합니다.

## 검증 방법과 결과

2026년 10월 3일에 Apple M3 Pro와 메모리 18GB 환경의 Chrome 헤드리스 브라우저에서 WebGPU 어댑터를 확인하고 실제 모델을 실행했습니다. 아래 브라우저 검증은 개발 서버에서 실행했으며 운영 배포 검증은 아닙니다.

너비 390px의 Chrome 화면에서도 `AI 배치` 시트를 열어 브라우저 AI 선택 버튼과 안내 및 요청 예시가 보이는지 확인했습니다. 모바일 기기에서 모델 추론을 실행한 검증은 아닙니다.

| 요청 또는 상황 | 관찰한 결과 |
|---|---|
| `의자를 90도 회전해줘` | 모델의 각도 응답이 달라도 문장에 적힌 90도를 제안했습니다. 확인 전에는 기존 25도가 유지됐고 적용 후 90도가 저장됐습니다. 새로고침 뒤에도 90도였습니다. |
| `소파 옆에 화분을 놓아줘` | 작은 모델이 처음에는 소파를 대상으로 잘못 선택했습니다. 문장의 대상인 화분과 현재 배치의 소파를 확인하는 처리를 추가했습니다. 공간 탐색이 다른 방으로 밀어낸 사례도 발견해 소파와 같은 방에 놓도록 고쳤습니다. 확인 전에는 저장소가 그대로였고 적용 후 거실의 가구가 4개에서 5개로 늘었습니다. 새로고침 뒤에도 유지됐습니다. |
| `창가에 의자를 옮겨줘` | 모델이 왼쪽 위치를 내놓았지만 요청의 창가 위치로 바로잡았습니다. 거실 창가에는 다른 가구와 충돌하지 않는 자리가 없어 이동을 거절하고 배치를 유지했습니다. |
| WebGPU를 사용할 수 없는 브라우저 | 다운로드를 시작하지 않고 WebGPU 안내를 표시했습니다. 기존 배치가 유지됐고 규칙 기반 데모로 전환할 수 있었습니다. |
| 규칙 기반에서 `소파를 삭제해줘` | 기존에는 소파를 추가하던 오류를 수정했습니다. 이제 삭제 확인 창을 표시합니다. |

프론트엔드 변경은 `frontend/`에서 `vp check`와 `vp test`와 `vp run build`로 검증합니다. `vp test`에는 모델 응답 검증과 제안 확인 흐름과 삭제 회귀 검사가 포함됩니다.

브라우저의 적용과 취소 및 오류 복구를 반복 검사하려면 `vp run test:e2e:local-ai`를 실행합니다. [브라우저 AI E2E 안내](../qa/local-ai-e2e.md)에 검사 사례와 실행 방법을 기록했습니다. 이 자동화는 모델 응답과 WebGPU 감지 경계를 통제하므로 위의 실제 모델 실행 결과와 구분합니다.

## 남은 한계

0.6B 모델은 짧은 한국어 문장도 잘못 분류할 수 있습니다. 명확한 가구와 동작은 문장과 카탈로그를 다시 대조하지만 여러 동작이 섞이거나 대상이 없는 요청은 처리하지 않습니다. 사용자는 제안을 확인한 뒤 적용해야 합니다. `Qwen3 1.7B ONNX`의 `q4f16`은 같은 Chrome 검증 환경에서 모델을 준비하는 동안 `std::bad_alloc`로 실패했으므로 기본 모델로 사용하지 않았습니다. Safari와 모바일 기기와 실제 WebXR 헤드셋에서는 이 모델을 검증하지 않았습니다.
