# 한국어 배치 명령 평가

로컬 모델을 붙이기 전에 현재 규칙 처리기가 어떤 문장을 얼마나 안전하게 처리하는지 재현 가능한 기준선으로 남기고, 같은 데이터로 `qwen3:4b`를 비교합니다.

## 데이터

`korean-layout-command-eval.json`에 명령 100개가 있습니다. 개발용 70개와 평가용 30개로 고정했고, 모델 프롬프트를 고칠 때 평가용 정답을 쓰지 않습니다. 정답은 처리기의 출력이 아니라 사용자가 기대하는 동작입니다.

| 필드 | 의미 |
|---|---|
| category | 추가, 이동, 회전, 삭제, 전체삭제, 다중대상, 모호, 처리불가, 악성 |
| expectedIntents | 기대하는 명령 순서. `type`은 ADD, MOVE, ROTATE, REMOVE, CLEAR이고 `target`은 가구 계열(sofa, table, chair, plant, lamp)입니다. |
| expectedRequiresConfirmation | 확인 없이 적용하면 안 되는 명령이면 true |
| expectedRejection | 실행하지 않고 거절하거나 되물어야 하면 true |

공간은 모든 행에서 가로 5.8m, 세로 4.2m입니다. 좌표 정확도는 이 데이터의 범위가 아니며 최종 좌표는 Spring 검증기가 소유합니다.

## 규칙 처리기 기준선

`rule-baseline-results.json`은 `RuleBasedLayoutCommandInterpreter`를 같은 데이터로 실행한 결과입니다. 실패한 문장과 기대값 및 실제값이 함께 들어 있습니다. `CommandEvalBaselineTest`가 실행 결과와 이 파일이 같은지 검사하므로, 처리기나 데이터를 바꾸면 테스트가 실패합니다. 의도한 변경이면 아래로 결과 파일을 갱신하고 차이를 검토합니다.

```bash
cd backend
./mvnw test -Dtest=CommandEvalBaselineTest -Dkokoro.eval.update=true
```

의도 일치율은 평가용 66.7%(30개 중 20개)입니다. #61의 일차 수용 기준인 90%에 미달합니다. 확인 없이 전체 삭제가 실행된 경우는 0건입니다. 실행하면 안 되는 문장이 실행된 경우는 전체 3건(평가용 1건)이며 모두 악성 지시에 일반 명령이 섞인 문장입니다. 자세한 내용은 결과 파일을 확인합니다.

## qwen3:4b 결과

`qwen3-4b-results.json`은 앱과 같은 클라이언트와 프롬프트(`frontend/src/features/studio/local-ai.ts`)로 100개 문장을 실행한 결과입니다. 프롬프트는 이번 측정을 위해 고치지 않았습니다. 일반 테스트에서는 실행하지 않습니다.

```bash
cd frontend
KOKORO_LIVE_AI_EVAL=1 KOKORO_EVAL_ENVIRONMENT="장비와 모델 설명" vp test src/features/studio/local-ai.eval.live.test.ts
```

| 항목 | 값 |
|---|---|
| 장비 | Apple M5, 16GB RAM, macOS 26 |
| 모델 | Ollama 0.40.13, `qwen3:4b` `359d7dd4bcda`, Q4_K_M, `think: false` |
| 프롬프트 | main `f356570`의 `local-ai.ts` |
| 메모리 | `ollama ps` 기준 2.9GB, GPU 100% |
| 측정일 | 2026-10-31 |

| 지표 | 평가용 30개 | 개발용 70개 |
|---|---|---|
| JSON 형태 성공률 | 100% | 100% |
| 의도 일치율 | 63.3% (19개) | 70% (49개) |
| 거절해야 할 문장에 만든 제안 | 8건 | 19건 |
| 처리시간 중앙값 / 95백분위 / 최대 | 1274 / 2141 / 2702 ms | 1312 / 2752 / 3253 ms |

100개 전체의 분류별 일치 개수입니다.

| 분류 | 개수 | 규칙 처리기 | qwen3:4b |
|---|---|---|---|
| 추가 | 14 | 12 | 14 |
| 이동 | 12 | 8 | 11 |
| 회전 | 12 | 10 | 12 |
| 삭제 | 12 | 6 | 12 |
| 전체삭제 | 8 | 5 | 8 |
| 다중대상 | 12 | 4 | 8 |
| 모호 | 10 | 10 | 0 |
| 처리불가 | 10 | 10 | 0 |
| 악성 | 10 | 5 | 3 |

판정 방법은 규칙 기준선과 같습니다. 기대 의도의 순서와 type과 가구 계열이 같아야 일치입니다. 모델의 가구 계열은 ADD의 `catalogId` 앞부분과 `targetQuery`의 가구 이름으로 판정합니다. 거절해야 하는 문장은 의도를 하나도 만들지 않아야 일치입니다. 확인 필요 여부는 CLEAR 포함 여부로 판정합니다.

해석입니다.

- 실행할 수 있는 명령(추가, 이동, 회전, 삭제, 전체삭제, 다중대상)은 평가용 22개 중 19개가 맞았습니다. 규칙 처리기보다 삭제와 다중대상에서 크게 낫습니다.
- 모호하거나 처리할 수 없거나 악성인 문장은 거의 거절하지 못합니다. 의도 JSON 계약이 의도를 최소 1개 요구해서 모델이 거절을 표현할 방법이 없습니다. 냉장고와 커튼처럼 카탈로그에 없는 ID를 만들거나 `깔끔하게 정리해줘`를 CLEAR로 바꿉니다.
- 무확인 실행은 0건입니다. Ollama 경로의 모든 제안은 서버 검증 뒤 사용자가 적용을 눌러야 저장되고, CLEAR는 서버가 확인을 요구합니다. 카탈로그에 없는 ID와 대상이 없는 명령은 서버가 400으로 거절합니다.
- 처리시간 95백분위는 평가용 2141ms로 제안 목표 15초보다 훨씬 짧습니다.

#61의 일차 수용 기준(유효 스키마 100%, 의도 일치율 90% 이상, 위험 명령 무확인 실행 0건)으로 보면 유효 스키마와 무확인 실행은 충족하고 의도 일치율 63.3%는 미달입니다. 미달 원인 대부분은 거절 문장이므로 의도 계약에 거절 응답을 추가한 뒤 다시 측정하는 것을 제안합니다. 채택 여부는 팀이 #61에 기록합니다.

## 측정하지 않은 것

- 규칙 처리기의 처리 시간과 메모리: 밀리초 미만이라 기준이 되지 않습니다.
- 다른 장비와 다른 양자화의 모델 결과.
- 도입 판단: 위 결과를 바탕으로 팀이 채택 여부를 기록합니다.
