# 시스템 구조

## 프로젝트 경계

### frontend

React 애플리케이션이 프로젝트 편집 흐름과 2D 도면 보기와 Three.js 3D 장면과 WebXR VR을 모두 담당합니다. 별도 VR 애플리케이션은 만들지 않습니다. 기본 로컬 데모에서는 브라우저 저장소를 사용합니다. `VITE_API_MODE=server`를 설정하면 Spring API를 프로젝트 상태의 최종 소유자로 사용합니다.

### backend

Spring Boot 애플리케이션이 프로젝트 생성과 도면 업로드와 배치 저장과 자연어 명령 처리를 담당합니다. 현재 구현은 개발용 메모리 저장소와 규칙 기반 명령 처리기입니다. 운영 전에는 PostgreSQL 저장소와 객체 저장소와 비동기 변환 작업 큐를 연결해야 합니다.

## 데이터 흐름

```text
도면 업로드
    ↓
Spring API가 파일 검증 및 변환 작업 생성
    ↓
도면 변환기가 벽과 문과 창문과 치수 모델 생성
    ↓
프론트엔드가 모델과 가구 배치를 Three.js로 렌더링
    ↓
챗봇 명령 또는 직접 조작으로 Furniture 배열 변경
    ↓
Spring API가 배치 저장
    ↓
같은 웹의 WebXR 세션이 배치를 실제 시점으로 표시
```

## 상태 소유권

| 상태 | MVP 소유자 | 운영 목표 |
|---|---|---|
| 프로젝트와 방 치수 | Spring 메모리 저장소 | PostgreSQL |
| 원본 도면 | 요청 처리 중인 서버 메모리 | S3 호환 객체 저장소 |
| 변환 작업 상태 | Spring 응답 | 작업 큐와 변환 작업자 |
| 3D 방 모델 | 예제 Three.js 장면 | GLB와 구조화된 공간 JSON |
| 가구 배치 | Spring 또는 로컬 데모 저장소 | PostgreSQL |
| 편집 중 카메라 | frontend | 저장하지 않음 |
| VR 렌더링 상태 | frontend WebXR 세션 | 저장하지 않음 |

## 운영 전 필수 작업

파일을 웹 요청 안에서 직접 변환하지 않습니다. 업로드가 끝나면 작업 식별자를 반환하고 별도 작업자가 변환해야 합니다. 사용자가 업로드한 도면은 민감한 주거 정보일 수 있으므로 접근 권한과 보존 기간과 삭제 기능이 필요합니다. AI 명령은 서버가 허용된 배치 동작으로 검증한 뒤 적용해야 합니다.
