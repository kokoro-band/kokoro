# 변경 경로별 CI

웹과 Spring은 각각 빌드합니다. 공유 API 명세나 데이터 형식을 바꾸면 두 영역을 함께 검사합니다. CI 설정이나 경로 판별 스크립트를 바꿀 때도 두 검사를 실행합니다.

| 변경 경로                                                     | 실행할 검사              |
| ------------------------------------------------------------- | ------------------------ |
| frontend                                                      | 웹 검사와 테스트 및 빌드 |
| backend                                                       | Spring 테스트와 패키지   |
| docs/contracts                                                | 웹과 Spring 모두         |
| .github/workflows 또는 .github/scripts                        | 웹과 Spring 모두         |
| flake.nix와 flake.lock 및 .envrc와 .tool-versions와 AGENTS.md | 웹과 Spring 모두         |
| README 등 일반 설명 문서                                      | 경로 판별과 최종 결과만  |

웹 변경은 브라우저 AI E2E와 실제 서버 E2E도 실행합니다. E2E는 브라우저에서 시작한 행동이 저장과 복구까지 이어지는지 검사하는 테스트입니다. 백엔드만 바꾸면 실제 서버 E2E를 실행하고 브라우저 AI E2E는 생략합니다. 공유 API 명세나 데이터 형식을 바꾸면 두 E2E 모두 실행합니다. CI 설정이나 공통 환경을 바꿀 때도 같습니다. 각 E2E의 desktop과 narrow 화면 작업은 기존처럼 나누어 실행합니다.

PR은 기준 브랜치와 작업 브랜치의 커밋을 비교합니다. main push는 이전 커밋과 현재 커밋을 비교합니다. 파일명은 널 문자로 구분하므로 공백이나 줄바꿈이 있어도 각각의 경로로 처리합니다. 커밋을 찾지 못하거나 판별이 실패하면 성공으로 넘기지 않습니다.

`CI result`는 항상 실행되며 필요한 빌드나 E2E가 실패하거나 취소되거나 생략되면 실패합니다. 두 화면 중 하나라도 실패하면 해당 E2E 작업 전체가 실패합니다. 필요 없는 검사의 생략만 허용합니다. 저장소에서 필수 검사 설정을 지원한다면 이 이름을 필수 검사로 지정합니다. 2026년 9월 25일 보호 설정 API는 요금제 제한으로 403을 반환했습니다. 당시 필수 검사 강제 설정을 확인하거나 변경하지 못했으며 현재 보호 상태는 별도 조회가 필요합니다.

성공한 실행에서는 `frontend-커밋SHA`와 `backend-커밋SHA` 빌드 파일을 7일 동안 보관합니다. 전자는 dist이며 후자는 실행 가능한 jar입니다. 각 배포가 동일한 실행의 커밋을 골라 사용해야 합니다. 이 워크플로는 운영 배포를 수행하지 않습니다.

같은 PR에 새 커밋을 올리면 진행 중인 이전 검사를 취소합니다. main은 실행마다 별도 그룹을 사용해 진행 중인 검사와 대기 중인 검사가 다른 커밋 때문에 취소되지 않도록 합니다. GitHub의 같은 그룹은 기본적으로 대기 중인 실행 하나만 보존하므로 취소 옵션만 끄는 것으로는 충분하지 않습니다. [GitHub의 동시 실행 안내](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)를 따릅니다.

파일 이동은 이전 경로의 삭제와 새 경로의 추가로 비교합니다. 예를 들어 frontend의 파일을 docs로 옮겨도 프론트 검사가 필요하다는 결과가 유지됩니다.

경로 판별과 실패 전파는 다음 명령으로 검사합니다.

```bash
node --test .github/scripts/ci-changes.test.mjs
```

실제 CI 실행 결과와 artifact 생성 여부는 PR의 Actions 링크에서 확인합니다. 경로별 조건의 단위 검사와 각 경로만 수정한 실제 PR 실행은 별개의 검증입니다.
