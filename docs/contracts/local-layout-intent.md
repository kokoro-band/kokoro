# 로컬 배치 요청 JSON 형식

사용자 PC의 로컬 모델(브라우저가 `127.0.0.1:11434`의 Ollama를 호출)이 한국어 명령을 해석해 만드는 JSON입니다. 웹과 서버는 `local-layout-intent.schema.json`을 기준으로 같은 형태를 검사합니다. 이 JSON은 수행할 배치 작업만 표현하며 저장할 좌표를 정하지 않습니다.

## 형태

```json
{ "version": 1, "intents": [{ "type": "MOVE", "targetQuery": "소파", "anchorQuery": "창가" }] }
```

| type | 필수 필드 | 선택 필드 | 의미 |
|---|---|---|---|
| ADD | `catalogId` | `count`(1~5), `anchorQuery`, `relation` | 등록된 가구를 추가합니다. |
| MOVE | `targetQuery` | `anchorQuery`, `relation` | 배치된 가구를 옮깁니다. |
| ROTATE | `targetQuery`, `rotation` | | 가구의 새 회전각(도, -360~360)입니다. 절대각이며 현재 각도에 더하지 않습니다. |
| REMOVE | `targetQuery` | | 배치된 가구를 삭제합니다. |
| CLEAR | | | 모든 가구를 삭제합니다. 서버가 항상 확인을 요구합니다. |

- `intents`는 1~10개이고 순서대로 처리합니다.
- `targetQuery`와 `anchorQuery`는 사용자가 말한 표현이며 100자 이하의 공백이 아닌 문자열입니다. 모델은 가구 ID를 추측하지 않고 서버가 배치된 가구에서 후보를 찾습니다.
- `catalogId`는 서버 카탈로그에 등록된 ID여야 합니다. 형식이 맞아도 등록되지 않은 ID는 서버가 거절합니다.
- `relation`은 `NEAR`(기준 가까이) 또는 `FAR_FROM`(기준에서 멀리)이며 `anchorQuery`가 있을 때만 쓸 수 있습니다. 생략하면 서버가 `NEAR`로 처리합니다. `anchorQuery`가 창문이나 문 중 무엇을 뜻하는지는 서버가 사용자 표현으로 해석합니다.
- `rotation`이 절대각이므로 "45도 더 돌려줘" 같은 상대 회전은 이 버전에서 표현할 수 없습니다. 모델은 사용자가 목표 각도를 말했을 때만 `ROTATE`를 만들어야 하며, 상대 회전이 필요하면 `rotationDelta` 같은 필드를 다음 배치 요청 버전에 추가합니다.
- 정의되지 않은 필드는 모두 거절합니다. 그래서 `x`와 `z` 같은 좌표를 모델이 반환할 수 없습니다.

## 책임

| 주체 | 책임 |
|---|---|
| 브라우저 | 모델 응답을 이 스키마로 검사합니다. 실패하면 서버에 보내지 않고 배치를 유지합니다. |
| 서버 | 스키마를 다시 검사하고 카탈로그 ID와 대상 후보를 확인한 뒤 확인이 필요한 제안을 만듭니다. 최종 좌표와 저장은 서버의 배치 검증기가 처리합니다. |
| 사용자 | 서버가 검증한 미리보기를 확인하거나 취소합니다. |

`anchorQuery`가 있는 명령의 좌표 계산은 #62에서 연결합니다. 그 전에는 서버가 `anchorQuery`를 처리하지 않는다고 응답하며 배치는 바뀌지 않습니다. 이 동작은 서버 이슈(#161)에서 구현합니다.

## 예제

`docs/contracts/fixtures/local-layout-intent.json`에 유효한 예제 8개와 거절해야 하는 예제 13개가 있습니다. 두 구현은 같은 예제를 기준으로 검사해야 합니다. 예제는 이 스키마를 draft 2020-12 검사기로 실행해 확인했습니다.
