# 공간 데이터 계약

사용자가 만든 방 구조와 가구 배치를 표현하는 형식입니다. 프론트엔드의 3D 생성과 WebXR, 백엔드 저장, 가구 배치 검증이 모두 이 형식을 사용합니다.

## 좌표계와 단위

API의 모든 점은 정확히 두 숫자를 가진 `[x, z]` 배열입니다. 외곽선과 벽 양 끝 및 방 영역과 시작 위치에 같은 규칙을 적용합니다. 객체 좌표와 문자열 숫자 및 유한하지 않은 값은 요청에서 거부합니다. 과거 PostgreSQL에 저장된 `{x, z}` 좌표는 저장소에서 읽을 때만 배열 형식으로 변환합니다. 이후 응답과 저장은 배열 형식을 사용합니다.

`fixtures/room-v2.json`은 웹 편집기가 생성한 문과 창이 있는 ㄱ자 방 예제입니다. 웹 테스트와 Spring API 테스트가 이 파일을 함께 사용합니다.

- 길이 단위는 미터입니다. 평수 같은 입력값은 저장하되 계산에는 사용하지 않습니다.
- 바닥면 좌표는 `[x, z]` 두 값이며 위에서 내려다본 평면입니다. `x`는 오른쪽, `z`는 아래쪽이 양수입니다.
- 원점은 `bounds` 바운딩 박스의 왼쪽 위 모서리입니다.
- 높이는 `y`이며 바닥이 0입니다.
- 3D 장면에서는 바운딩 박스의 중심이 월드 원점에 오도록 옮겨 그립니다. 저장 데이터는 항상 위 원점을 기준으로 합니다.

## RoomModel

저장 전에 서버가 버전과 단위 및 공간의 형태를 검증합니다. 외곽선은 자기 교차가 없는 3~512점 다각형이어야 합니다. 가로와 세로는 0.5~200m이고 층고는 0.5~20m입니다. 벽과 문창은 각각 최대 1024개이며 식별자가 중복될 수 없습니다. 문창은 참조하는 벽의 길이와 높이 안에 있어야 하고 같은 벽에서 서로 겹칠 수 없습니다.

방 이름 영역은 최대 128개이며 전체 좌표는 4096점 이내입니다. 시작 위치와 방 영역은 외곽선 안에 있어야 합니다. 선택 필드는 생략할 수 있지만 입력한 값은 검증합니다. 형식이 맞지 않는 공간은 저장하지 않으며 오류에는 `code: INVALID_ROOM`과 `violations`의 `path` 및 `reason`을 담습니다. 이전 공간과 배치 및 저장 시각은 유지합니다.

```json
{
  "version": 2,
  "unit": "m",
  "wallHeight": 2.4,
  "bounds": { "width": 10.4, "depth": 6.4 },
  "outline": [[0, 0], [10.4, 0], [10.4, 3.4], [7.9, 3.4], [7.9, 5.0], [6.4, 5.0], [6.4, 6.4], [0, 6.4]],
  "walls": [
    { "id": "w01", "a": [0, 0], "b": [10.4, 0], "thickness": 0.2 }
  ],
  "openings": [
    { "id": "o01", "wallId": "w01", "type": "door", "from": 0.4, "to": 1.3, "bottom": 0, "top": 2.1 }
  ],
  "rooms": [
    { "name": "거실", "polygon": [[3.2, 2.6], [6.4, 2.6], [6.4, 6.4], [3.2, 6.4]] }
  ],
  "spawn": [4.8, 4.6],
  "source": { "areaPyeong": 20, "roomCount": 3, "preset": "grid-v1" }
}
```

| 필드 | 설명 |
|---|---|
| `version` | 스키마 버전입니다. 현재 `2`입니다. |
| `unit` | 항상 `"m"`입니다. |
| `wallHeight` | 층고입니다. |
| `bounds` | 외곽 바운딩 박스입니다. 좌표 원점의 기준이며 카메라와 격자 크기를 정할 때 사용합니다. |
| `outline` | 바닥 외곽 다각형입니다. 마지막 점은 첫 점과 이어집니다. 직사각형이 아닌 평면을 표현하고 바닥 생성과 이동 가능 범위 판정에 사용합니다. |
| `walls` | 벽 목록입니다. `a`와 `b`는 벽 중심선의 양 끝이고 `thickness`는 두께입니다. 두께는 약 `2.22e-16`인 `Number.EPSILON` 이상이며 200m 이하입니다. 처리 가능한 데이터 경계이며 권장 시공 치수는 아닙니다. |
| `openings` | 문과 창입니다. `wallId`가 가리키는 벽에 종속되며 `from`과 `to`는 벽의 `a`에서 잰 거리, `bottom`과 `top`은 바닥에서 잰 높이입니다. `type`은 `door` 또는 `window`입니다. |
| `rooms` | 방 이름과 영역입니다. 표시용이며 3D 생성에는 필수가 아닙니다. |
| `spawn` | VR 진입 위치입니다. 없으면 바운딩 박스 중심을 사용합니다. |
| `source` | 사용자가 방을 만들 때 입력한 값입니다. 같은 입력으로 방을 다시 생성할 때 사용합니다. 손으로 만든 데이터에는 없을 수 있습니다. |

`source.preset`은 입력값으로 방을 배치하는 규칙의 식별자입니다. 규칙이 바뀌어도 기존 프로젝트를 같은 모양으로 다시 만들 수 있도록 남깁니다.

## 가구 배치

```json
{
  "id": "sofa-01",
  "catalogId": "sofa-cloud",
  "name": "클라우드 소파",
  "category": "소파",
  "x": 2.4,
  "z": 4.6,
  "rotation": 0,
  "color": "#D8C8B8"
}
```

- `x`와 `z`는 `RoomModel`과 같은 좌표계의 미터 값입니다. 가구의 바닥 중심 위치입니다.
- `rotation`은 도 단위이며 위에서 봤을 때 시계 방향입니다. 0도는 가구의 정면이 `+z`를 향하는 상태입니다.
- 크기는 저장하지 않습니다. `catalogId`로 카탈로그의 폭과 깊이를 참조합니다.

## 검증 규칙

- 가구의 회전된 바닥 사각형이 `outline` 다각형 안에 있어야 합니다. 경계선에 닿는 것은 허용합니다.
- 가구끼리 겹치지 않아야 합니다.
- 하나라도 실패하면 배치 전체를 저장하지 않고 사유를 반환합니다.
- 공간 데이터가 없는 프로젝트는 `dimensions` 크기의 직사각형을 외곽선으로 간주합니다.

## 변경 이력

| 버전 | 내용 |
|---|---|
| 1 | 최초 정의. 가구 좌표는 방 크기 대비 백분율이었습니다. |
| 2 | 가구 좌표를 미터로 바꾸고 `source`를 추가했습니다. 도면 이미지 자동 인식 대신 사용자가 방을 만드는 방식으로 바뀌면서 변환 결과 계약을 이 문서로 통합했습니다. |
