# GitHub Pages 데모

데모 주소는 https://kokoro-band.github.io/kokoro/ 입니다. 로그인이나 서버 설치 없이 브라우저에서 구조를 편집하고 가구를 배치할 수 있습니다.

## 데모에서 가능한 작업

방 구조를 만들고 가구를 옮긴 뒤 같은 배치를 2D와 3D로 확인합니다. 작업은 방문자의 브라우저에 저장됩니다. 같은 브라우저에서 새로고침하면 저장한 배치를 다시 열 수 있습니다. 다른 기기와 데이터를 공유하지 않으며 브라우저 저장소를 지우면 작업도 사라집니다.

Spring API와 DB 및 Ollama는 이 배포에 포함되지 않습니다. 자연어 명령은 프론트엔드에 구현된 규칙으로 처리합니다. 도면 파일 업로드와 이미지 분석의 지원 범위는 [제품 문서](../PRODUCT.md)를 따릅니다. GitHub Pages의 HTTPS 주소는 웹 VR 접속에 사용할 수 있지만 실제 헤드셋과 컨트롤러의 동작은 별도로 확인해야 합니다.

## 자동 배포

CD는 코드 변경을 검사하고 웹사이트에 자동으로 게시하는 과정입니다. [GitHub Pages 데모 워크플로](../.github/workflows/pages.yml)가 프론트엔드를 검사하고 테스트와 빌드를 완료한 결과만 게시합니다.

| 발생한 작업 | 결과 |
|---|---|
| 워크플로가 반영된 `main`의 프론트엔드 또는 공유 API 명세와 데이터 형식 및 배포 설정 변경 | `main`의 화면을 자동 게시합니다. |
| 프론트엔드 또는 공유 API 명세와 데이터 형식 및 배포 설정을 바꾸는 PR | 데모용 경로로 테스트와 빌드를 검사합니다. 사이트는 바꾸지 않습니다. |
| `main`에서 수동 실행 | 검사 후 `main`을 게시합니다. |
| 다른 브랜치에서 이 워크플로 수동 실행 | 빌드만 검사하고 배포 단계는 생략합니다. |

최초 공개 데모는 `codex/github-pages-demo`의 `0687741`로 게시했습니다. #98 통합 변경이 main에 들어가기 전에는 공개 화면이 그대로 유지됩니다. 통합 PR의 성공은 실제 main 배포 성공을 뜻하지 않습니다.

저장소의 Settings > Pages에서 Source를 GitHub Actions로 설정합니다. main 배포로 전환할 때 `github-pages` 환경의 허용 브랜치를 `main`만 남기고 초기 데모 브랜치의 실행 중인 배포와 예약된 배포가 없는지 확인합니다. 과거 브랜치에는 예전 워크플로가 남아 있으므로 이 정책 변경 없이 코드만 병합하면 예전 화면이 다시 게시될 수 있습니다. 환경 정책 변경은 이 PR에서 실행하지 않았습니다. 배포 권한은 배포 단계에만 부여합니다.

빌드 환경에는 `VITE_API_MODE=local`과 `VITE_BASE_PATH=/kokoro/`가 지정됩니다. 두 번째 값은 사이트가 도메인 바로 아래가 아닌 `/kokoro/` 아래에 있다는 뜻입니다. 로고와 가구 모델도 이 경로를 기준으로 불러옵니다. 공통 가구 JSON의 `/models/` 경로는 웹과 서버에서 같은 값으로 유지하며 웹의 모델 로더에서만 실제 배포 경로를 붙입니다. 로컬 개발은 설정이 없으면 기존 `/` 경로를 사용합니다.

## 배포 확인과 재실행

GitHub의 Actions에서 GitHub Pages 데모 실행을 열어 build와 deploy가 모두 성공했는지 확인합니다. 그다음 데모 주소에서 로고와 가구가 표시되는지 확인하고 배치를 바꾼 뒤 새로고침해 저장된 결과를 확인합니다. 빌드 성공만으로 화면과 웹 VR 검증을 대신하지 않습니다.

실행이 실패하면 해당 실행의 Re-run failed jobs로 다시 실행할 수 있습니다. 빌드 실패 시 기존 사이트는 유지됩니다. Run workflow에서는 `main`을 선택해 게시합니다. 화면을 이전 상태로 되돌려야 하면 원인이 된 변경을 되돌리는 커밋을 리뷰 후 main에 반영합니다. 초기 데모 브랜치를 재배포하는 방식으로 복구하지 않습니다.

## 로컬에서 배포 빌드 확인

```bash
cd frontend
vp install
vp check
vp test
VITE_API_MODE=local VITE_BASE_PATH=/kokoro/ vp test
VITE_API_MODE=local VITE_BASE_PATH=/kokoro/ vp run build
VITE_BASE_PATH=/kokoro/ vp preview
```

미리보기 주소는 `http://localhost:4173/kokoro/`입니다. 이 명령은 배포 결과를 로컬에서 확인하는 용도입니다.

## main 통합 계획

1. 기존 커서와 숫자 단축키 및 Pages 변경을 최신 main에 맞춰 적용합니다.
2. 방 크기 조절과 공통 카탈로그 및 문 열림 방향의 기존 테스트를 유지합니다.
3. 기본 경로와 하위 경로 테스트를 실행하고 실제 배포 빌드의 커서 및 저장 복원을 브라우저에서 확인합니다.
4. #94의 벽과 문 및 #96 저장 복구와 #100 VR 검사는 각 PR에서 이어갑니다. 이 변경은 해당 PR을 대신하거나 병합하지 않습니다.
5. 승인된 통합 PR이 main에 반영되면 배포 환경 정책을 main으로 제한하고 배포 커밋과 실제 화면을 확인한 뒤 #98을 완료합니다.

실패 테스트는 `3e37678`에서 실행했습니다. main의 숫자 키를 이용한 화면 전환 동작과 서로 다른 배포 경로의 모델 캐시가 기대 결과와 달라 3개 중 2개가 실패했습니다. 통합 후 같은 테스트를 통과시켰습니다. 가져온 커서 이벤트 테스트와 단축키 DOM 테스트는 기존 기능을 확인하는 테스트입니다.

## 통합 검증 결과

2026년 9월 28일 기준으로 기본 경로와 `/kokoro/` 경로에서 각각 17개 테스트 파일의 193개 테스트가 통과했습니다. `vp check`와 두 경로의 빌드도 통과했습니다. 빌드에는 기존 대형 번들 경고가 남아 있습니다.

로컬 배포 빌드의 브라우저에서 다음 결과를 확인했습니다.

- 로고와 실제 가구 모델이 표시됩니다.
- 가구 이동 도구는 가구 좌표를 바꿉니다. 화면 이동 도구는 가구 좌표를 유지한 채 화면만 옮깁니다.
- 3D에서 고른 도구가 2D로 바꿔도 유지됩니다.
- 숫자 입력칸에서 값을 바꿀 때 화면이 전환되지 않습니다. 저장한 가로 좌표 4.6m와 세로 좌표 5.6m가 새로고침 후 복원됩니다.
- 확인한 동작에서 브라우저 콘솔 오류가 없었습니다.

공개 사이트의 main 배포와 실제 VR 헤드셋 동작은 아직 검증하지 않았습니다. #98은 실제 배포 확인까지 열린 상태로 유지합니다.

## 저장소 공개 범위

저장소를 Public으로 전환하면 웹 데모와 함께 저장소의 코드와 커밋 이력 및 이슈와 PR도 공개됩니다. 데모에 입력한 배치는 방문자의 브라우저 안에 저장되며 GitHub 저장소에 업로드되지 않습니다.

설정 근거는 [GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)와 [Vite 배포 안내](https://vite.dev/guide/static-deploy#github-pages)입니다.
