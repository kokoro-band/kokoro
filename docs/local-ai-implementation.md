# 사용자 PC의 자연어 배치 구현 계획

## 목표

브라우저에서 한국어로 가구를 요청하면 사용자 PC의 모델이 해석합니다. 서버가 등록된 가구와 실제 공간을 기준으로 명령을 검증하고 미리보기를 반환합니다. 사용자가 확인하면 서버에 저장되며 새로고침 후에도 같은 배치가 나타나야 합니다.

아래에는 단계별 구현 기록이 있습니다. 최신 결과는 마지막 검증 기록을 기준으로 읽습니다. 기존 규칙 배치를 로컬 모델의 결과로 가장하지 않습니다. 실행 방법은 [로컬 AI 실행 안내](local-ai-runbook.md)에 있습니다.

## 실행 경계

- React와 SEED Design 및 Three.js를 유지합니다. Spring과 PostgreSQL이 저장을 담당합니다.
- 모델은 사용자 PC의 Ollama입니다. 브라우저가 `http://127.0.0.1:11434`만 호출합니다. Spring에서 해당 주소를 호출하지 않습니다.
- 모델 다운로드 후 추론에는 외부 AI API가 필요하지 않습니다. 검증에서는 `OLLAMA_NO_CLOUD=1`을 사용합니다.
- 브라우저 접속 허용 주소는 앱 주소로 지정합니다. 모든 웹사이트를 허용하는 설정은 안내하지 않습니다.
- 모델이 반환한 텍스트는 신뢰하지 않습니다. JSON 형식과 허용된 명령 및 서버 카탈로그의 ID를 검증합니다. 코드와 URL은 실행하지 않습니다.
- 도면 원본 이미지와 인증 토큰 및 다른 사용자의 데이터는 모델에 전달하지 않습니다.

## 성공 조건

1. 서버 DB에 가구 정보가 초기 등록되고 반복 시작에도 중복되지 않습니다. 모델의 출처와 예제 치수 및 예제 가격이 구분됩니다.
2. 실제 로컬 모델로 추가와 이동 및 회전과 삭제 및 전체 삭제를 해석합니다. 같은 가구가 여러 개면 사용자 선택을 받습니다.
3. 상대 위치의 최종 좌표는 서버가 계산합니다. 내부 벽과 외곽 및 다른 가구와 충돌하는 후보는 적용하지 않습니다.
4. 서버가 검증한 제안만 확인할 수 있습니다. 취소와 만료 및 프로젝트 변경은 제안을 적용하지 않습니다.
5. 확인은 한 번만 적용됩니다. 응답을 잃으면 같은 제안의 상태를 확인하고 재실행하지 않습니다.
6. 실제 웹 입력부터 모델과 서버 및 DB를 거쳐 새로고침까지 검증합니다. 모델을 끈 상태와 잘못된 응답 및 오래된 제안도 검사합니다.

## 저장과 확인 규칙

프로젝트의 `revision`은 변경할 때마다 증가하는 버전 번호입니다. 시간 문자열이나 내용 비교만으로 오래된 제안을 판단하지 않습니다. 같은 값으로 되돌아온 프로젝트도 과거 제안을 다시 적용할 수 없습니다.

모든 편집 쓰기는 같은 프로젝트 행을 잠근 뒤 최신 상태와 요청한 버전을 확인합니다. 잠금은 다른 요청이 동시에 같은 프로젝트를 변경하지 못하게 하는 DB 기능입니다. 모델 추론 중에는 잠금을 잡지 않습니다. 비동기 도면 작업은 도면 필드만 갱신하고 전체 가구 목록을 다시 저장하지 않습니다.

제안에는 소유자와 프로젝트 및 기준 버전과 명령 및 만료 시각과 처리 결과를 저장합니다. 확인 요청은 제안 ID만 받습니다. 전체 명령을 검증하고 한 트랜잭션으로 적용합니다. 트랜잭션은 일부만 저장되는 일을 막는 DB 처리 단위입니다.

브라우저는 명령 전에 남은 저장 요청을 마칩니다. 확인 요청부터 처리 상태 확인까지 수동 편집과 되돌리기 및 업로드를 잠급니다. 오래된 응답은 프로젝트 세대 번호로 버립니다. 이미 서버로 보낸 쓰기를 취소하는 것만으로 저장 안전성을 보장하지 않습니다.

## 검증과 미검증의 구분

프론트는 `vp check`와 `vp test`와 `vp run build`를 실행합니다. 백엔드는 `./mvnw test`와 `./mvnw package`를 실행합니다. 별도의 DB 연결로 확인과 저장 및 도면 완료와 중복 확인 및 취소 경합을 검사합니다. 실제 Ollama 테스트는 모의 응답 테스트와 구분합니다.

헤드셋 검증과 운영 배포는 이 목표의 로컬 자연어 검증과 별도입니다. 미병합 선행 PR은 격리 작업 폴더에서만 결합합니다. 원격 main이나 기존 PR을 승인 없이 병합하지 않습니다.

### 수정한 실패 사례

단순 추가 요청이 앞선 예시의 기준 가구를 이어받는 문제가 실제 모델 검사에서 드러났습니다. 예시를 이전 대화가 아닌 별도의 참고 자료로 전달하도록 바꿨습니다. 창가를 기준 가구 이름으로 반환하는 경우도 있어 문과 창문은 가구 기준이 아니라는 규칙을 명시했습니다. 실패했던 문장도 실제 모델 회귀 검사에 남겼습니다. 이 검사는 임의의 한국어 표현 전체의 정확도를 보장하지 않습니다.

독립 코드 검토에서 다섯 문제를 수정했습니다. 같은 요청의 추가 가구 ID를 선택 재요청에서도 유지합니다. 방의 방향 계산은 선택한 방의 좌표 범위를 사용합니다. 미완료 제안 복구는 원래 프로젝트를 먼저 불러옵니다. 저장본 복구는 캐시 대신 서버에 다시 요청하며 진행 중인 저장이 끝날 때까지 기다립니다. 각각 회귀 테스트를 추가했고 해당 검토 범위에서 GREEN을 받았습니다.

### 실행한 검사와 남은 경계

- 프론트 `vp check`와 `vp test` 및 `vp run build`를 실행했습니다. 일반 테스트 146개를 통과했습니다. 기본 실행에서 실제 모델 검사 11개와 서버 연쇄 검사 1개는 의도적으로 제외하며 별도 실행으로 확인했습니다.
- 백엔드 `./mvnw test`와 `./mvnw package`를 실행했습니다. PostgreSQL을 사용하는 검사까지 57개를 통과했습니다. 문 후보 선택과 잘못된 후보 거부도 포함됩니다.
- 빌드에는 큰 JavaScript 번들 경고가 남아 있습니다. 기능 실패는 아니며 성능 최적화 과제입니다.
- 확인한 환경은 같은 PC의 브라우저와 Ollama 및 개발용 Spring/PostgreSQL입니다. 다른 PC의 성능과 운영 HTTPS의 로컬 모델 접근 및 헤드셋은 이번 검증 범위가 아닙니다.
- 통합 브랜치는 여러 미병합 선행 PR을 결합한 상태입니다. main이나 운영 서버에 반영됐다는 뜻이 아닙니다. 기존 PR을 임의로 병합하지 않았습니다.
