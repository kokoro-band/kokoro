## 기준과 이번 작업의 범위

후속 통합에서는 #101 위의 #94를 이 테스트 기반에 합쳐 같은 트리에서 실행합니다. 기존 기록의 브랜치별 테스트 개수는 합산하지 않습니다. #96의 저장 변경은 이 기반 위에서 별도로 검증하고 화면 테스트는 #99에서 추가합니다. PR을 연결하는 작업은 GitHub 병합이나 공개 배포가 아닙니다.

2026년 9월 28일 main `a922ac8`을 기준으로 코드와 열린 이슈 25개 및 관련 PR을 대조했습니다. 이 문서는 제품 전체의 검증 계획입니다. 모든 동작 테스트가 이미 완성됐다는 뜻은 아닙니다.

## 테스트를 나누는 기준

#11의 테스트 환경은 2단계와 병행해서 만들 수 있습니다. 기능이 미통합된 동안 해당 흐름은 보류로 명시하며 의미 없는 skip이나 재시도로 초록 상태를 만들지 않습니다. 외부 유료 자원이나 새 인증 권한은 이 계획으로 승인되지 않습니다.

E2E는 테스트마다 고유 프로젝트를 만들고 해당 데이터만 정리합니다. 운영 데이터나 개발자의 작업 데이터를 지우지 않습니다. 단위 테스트에서는 지연 Promise와 제어 가능한 시간을 사용하고 브라우저에서는 화면 상태와 응답을 기다립니다. 실패 산출물은 화면과 trace 및 서버 로그를 남기되 토큰과 개인 도면은 제외합니다.

## 이번 실행 근거

새 테스트만 먼저 추가한 커밋은 `bfb584b`입니다. 기존 코드로 `vp test src/features/studio/vr-locomotion.test.ts`를 실행해 12개 중 6개가 실패했습니다. 실패는 아래 기대 결과의 불일치였으며 설치나 문법 오류가 아니었습니다.

1. 재입장 후 첫 회전이 실행되어야 합니다.
2. 이전 세션에서 잡은 상태가 다음 세션의 바닥 표시를 막지 않아야 합니다.
3. 연결이 끊긴 컨트롤러의 늦은 release가 이전 선택을 확정하지 않아야 합니다.
4. 세션 밖 선택 이벤트가 배치를 바꾸지 않아야 합니다.
5. XR이 변경한 카메라 위치와 방향이 종료 후 복원되어야 합니다.
6. 종료 시 레이의 기하와 재질 및 이벤트를 정리해야 합니다.

최소 수정 후 같은 검사와 VR 진입 안내 및 편집 이력 검사를 실행해 새 테스트 24개가 통과했습니다. 독립 리뷰 후 재연결 이벤트 순서와 실제 재마운트 및 머리 회전 방향 검사를 보완했습니다. 이 과정에서 늦은 release가 텔레포트로 해석되는 문제와 다른 손의 연결 해제가 추가 회전을 일으키는 문제 2건을 다시 실패 테스트로 확인한 뒤 수정했습니다. 최종 추가 테스트는 28개입니다.

편집 이력 5개와 VR 안내 7개는 기존 동작을 확인한 테스트이며 새 기능을 RED부터 개발했다고 주장하지 않습니다. Three 객체를 실제로 사용하지만 XR 장비와 renderer는 대체하므로 헤드셋 검증을 대신하지 않습니다.

최종 로컬 검증은 `vp check`와 17개 파일의 `vp test` 198개 및 `vp run build`가 통과했습니다. 번들 크기 경고는 남아 있습니다. 백엔드 코드는 이번에 변경하지 않았고 로컬 Maven 검사는 다시 실행하지 않았습니다. PR의 CI 결과와 실제 브라우저 및 헤드셋 결과는 각각 별도로 기록합니다.

로컬 브라우저에서 3D 화면을 연 뒤 VR 모드로 전환해 비지원 안내와 비활성 진입 버튼을 확인했습니다. 다시 3D로 돌아와 편집 화면이 표시됐고 확인 시점의 콘솔 오류는 없었습니다. 실제 XR 세션에 진입한 검증은 아닙니다.

독립 리뷰에서 발견한 편집 이력의 같은 태그 no-op 이후 첫 변경이 undo에 남지 않는 경우는 hook API 경계 문제입니다. 현재 화면에서 직접 재현된 문제로 단정하지 않으며 #99에서 회귀 테스트와 최소 수정으로 다룹니다. PR #96의 controller 구현은 이번 변경에 포함하지 않았습니다.

## 앞으로 PR에 남길 내용

새 기능과 버그 수정은 실패하는 기대 동작부터 작성합니다. `RED: 명령과 실패 이유` 및 `GREEN: 같은 명령의 통과 결과`를 PR 검증 항목에 적습니다. 이후 관련 회귀 검사와 `vp check`와 `vp test`와 `vp run build`를 실행합니다. 백엔드 변경은 `./mvnw test`와 `./mvnw package`를 실행합니다.

커버리지 숫자는 테스트가 어떤 줄을 실행했는지만 보여 줍니다. 필요한 동작이 맞는지는 위 표의 성공과 실패 결과로 판단합니다. CI가 통과했다는 사실만으로 테스트를 먼저 작성했다고 증명할 수 없으므로 리뷰에서 실패 근거와 변경 범위를 함께 확인합니다. 문서만 변경하거나 실기기 의존으로 자동화할 수 없는 경우는 이유와 대체 확인 및 후속 이슈를 명시합니다.
