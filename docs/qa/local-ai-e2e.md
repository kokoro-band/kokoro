# 브라우저 AI 동작 테스트

## 무엇을 확인하는가

E2E는 사용자의 화면 조작이 최종 결과까지 이어지는지 확인하는 검사입니다. 이 검사는 로컬 데모에서 브라우저 AI를 선택하고 요청을 보낸 뒤 제안을 검토하고 저장하는 흐름을 확인합니다. 이미 구현한 동작을 고정하는 회귀 검사입니다. 제품 코드를 일부러 바꿔 실패 기록을 만들지 않습니다.

각 사례를 너비 1280px의 desktop과 390px의 narrow에서 실행합니다. 화면 크기마다 12개씩 총 24개입니다.

| 사례 | 확인하는 결과 |
|---|---|
| 의자를 90도로 회전 | 모델이 0도를 답해도 사용자 문장의 90도를 제안합니다. 적용 전 저장값은 그대로입니다. 적용 후 새로고침에서도 프로젝트와 방이 유지되고 가구 목록에 90도가 표시됩니다. |
| 전체 삭제 취소 | 확인 전과 취소 후 저장값이 같습니다. 입력창으로 포커스가 돌아오며 새로고침한 내역에도 원래 가구가 남습니다. 좁은 화면에서 확인창과 입력 시트가 동시에 입력을 가두지 않습니다. |
| 소파 옆 화분 추가 | 모델이 소파를 추가하라고 답해도 화분을 제안합니다. 적용한 화분은 소파와 같은 거실에 가까이 놓입니다. 기존 가구를 유지하며 새로고침한 내역에도 화분이 남습니다. |
| 잘못된 모델 응답 | 깨진 JSON과 알 수 없는 동작 및 없는 카탈로그 항목을 각각 거절합니다. 저장값이 유지되며 규칙 기반으로 소파 삭제를 이어갈 수 있습니다. |
| WebGPU 사용 불가 | 브라우저 기능이 없거나 GPU 연결이 없거나 연결 검사에서 오류가 나는 세 경우를 확인합니다. 모델 Worker를 시작하지 않으며 규칙 기반으로 소파 삭제를 이어갈 수 있습니다. |
| Worker 실행 실패 | 오류 응답과 Worker 자체 종료를 각각 만듭니다. 배치를 보존하고 다음 AI 요청으로 회전 제안을 적용할 수 있습니다. |
| 생성 중 중단 | 요청 중단 뒤 입력창이 다시 활성화됩니다. 저장값을 보존하며 새 Worker의 다음 회전 요청은 적용됩니다. |

## 모델과 하드웨어 경계

Worker는 화면의 입력 처리를 막지 않도록 별도 실행 공간에서 모델을 돌리는 브라우저 기능입니다. Playwright가 모델 Worker의 스크립트 요청에 정해진 응답을 돌려줍니다. 브라우저의 실제 Worker 생성과 메시지 전달 및 종료는 그대로 사용합니다. WebGPU 사용 가능 여부만 브라우저 시작 전에 지정합니다.

앱의 응답 해석과 가구 대조 및 제안 계산과 확인창 및 브라우저 저장은 실제 코드를 사용합니다. 확인 전과 오류 후에는 저장한 JSON 문자열 전체를 비교합니다. 적용 후에는 저장된 가구와 방 및 프로젝트 ID와 새로고침한 화면을 확인합니다. 테스트마다 새 브라우저 저장소를 만들고 처음에만 전용 프로젝트를 넣습니다. 새로고침 때 저장 결과를 다시 초기값으로 덮어쓰지 않습니다.

외부 HTTP 요청은 차단하며 요청이 발생하면 검사도 실패합니다. 모델 파일을 다운로드하지 않으므로 실제 Qwen의 응답 품질과 GPU 추론 성능을 보장하는 검사는 아닙니다. 실제 모델과 Chrome에서 확인한 결과는 [WebGPU QA 기록](../ai/browser-webgpu-qa.md)을 따릅니다. 390px은 마우스로 조작하는 반응형 웹 검사입니다. 실제 휴대전화 추론과 Safari 및 WebXR 헤드셋 검증은 별도입니다.

## 실행 방법

Vite+와 Playwright의 Chromium이 필요합니다. Java와 Docker 및 모델 파일은 필요하지 않습니다. `frontend/`에서 실행합니다.

```bash
vp install
vp exec playwright install chromium
vp run test:e2e:local-ai
```

Linux에서 시스템 라이브러리도 준비할 때는 `vp exec playwright install --with-deps chromium`을 사용합니다. 화면 크기 하나만 검사할 수도 있습니다.

```bash
vp run test:e2e:local-ai --project=desktop
vp run test:e2e:local-ai --project=narrow
```

인자가 없으면 두 크기를 검사합니다. 위 두 인자 중 하나만 허용하며 다른 옵션은 서버 시작 전에 거절합니다. 실행기는 비어 있는 로컬 포트를 고르고 로컬 데모 모드의 Vite만 시작합니다. 기존 서버를 재사용하지 않으며 외부 API 환경변수와 추가 런타임 옵션을 전달하지 않습니다. 완료와 실패 및 중단 때 자신이 시작한 프로세스 그룹을 정리합니다. 실행 전체 제한은 5분이며 Windows 직접 실행은 지원하지 않습니다.

테스트별 제한은 60초이며 재시도는 없습니다. 고정 시간 대기를 사용하지 않고 화면 상태가 바뀔 때까지 기다립니다. `playwright-report/`에서 결과를 보고 실패 시 `test-results/`의 화면과 실행 기록으로 원인을 확인합니다. 같은 체크아웃에서 검사 두 개를 동시에 실행하면 결과 폴더가 겹치므로 한 번에 하나씩 실행하세요.

CI는 `local-ai-e2e`의 두 화면 작업으로 실행하며 한쪽 실패가 다른 쪽을 취소하지 않습니다. 실패 자료는 화면 크기와 실행 ID가 포함된 이름으로 7일 보관합니다. 기존 `test:e2e`는 [실제 Spring 서버와 DB 검사](server-e2e.md)를 계속 실행합니다. 로컬 AI 검사가 기존 서버 검사에 섞이지 않도록 설정을 분리했습니다. PR의 CI 통과와 main 반영 및 운영 배포는 별도 결과입니다.

## 작성과 로컬 실행 기록

2026년 10월 4일 macOS의 Playwright Chromium에서 24개가 재시도 없이 통과했습니다. `vp check`와 `vp run typecheck:e2e` 및 `vp run build`도 통과했습니다. 전체 단위 검사는 48개 파일의 739개가 통과했습니다. 빌드의 기존 큰 번들 경고는 남습니다. 테스트 목록으로 기존 서버 34개와 로컬 AI 24개가 섞이지 않는 것도 확인했습니다. 이 목록 확인은 실제 서버 테스트 실행 결과가 아닙니다.

첫 실행에서는 요청 중에 입력창도 비활성화된다는 잘못된 가정과 좁은 화면의 시트 뒤에 있는 앱 상단 표시를 읽으려는 조건을 수정했습니다. 제품 결함으로 계산하지 않습니다. 사용자는 생성 중 다음 문장을 입력할 수 있으며 중복 요청 전송은 비활성화됩니다. 저장 완료는 실제 저장값으로 확인합니다.

별도로 macOS의 프로세스 정리 중 오류를 발견했습니다. 이미 종료 신호를 보낸 그룹의 존재를 확인하는 동안 일시적으로 `EPERM`이 반환됐습니다. `EPERM`은 해당 확인이 허용되지 않았다는 오류이며 프로세스가 사라졌다는 뜻이 아닙니다. 수정 전 `vp test e2e/process-groups.test.ts`에서 새 존재 확인 사례가 실패했습니다. 수정 후 4개가 모두 통과했습니다. 존재 확인이 거절되면 그룹을 계속 추적하고 다시 확인합니다. 실제 종료 신호가 거절되면 여전히 정리 실패로 처리합니다.

경계를 통제하는 방법은 Playwright의 [네트워크 응답 대체](https://playwright.dev/docs/mock)와 [브라우저 시작 전 스크립트](https://playwright.dev/docs/api/class-browsercontext#browser-context-add-init-script) 안내를 따릅니다.
