# Ollama 배치 화면 연결 검증

## 범위와 선행 작업

#164는 #175의 Ollama 클라이언트 위에서 서버 저장 모드의 AI 배치 화면을 연결합니다. 서버의 `POST /projects/{id}/layout/intents`는 #168이 필요합니다. #175만 있는 서버에는 이 API가 없으므로 요청 실패를 안내하고 기존 배치를 유지합니다. 상대 위치는 별도 서버 작업 #174의 범위입니다.

`이 PC의 Ollama 사용`을 고르면 서버 카탈로그의 ID와 이름 및 치수를 받아 #175의 클라이언트로 요청을 해석합니다. 검사한 JSON과 프로젝트 버전을 Spring으로 보내고 서버의 제안을 기존 확인 화면에서 확인하거나 취소합니다. 후보 선택은 이미 검사한 JSON을 재사용하며 모델을 다시 실행하지 않습니다. 설치와 브라우저 접근 설정은 [Ollama 실행 안내](../ai/local-ollama-setup.md)를 따릅니다.

## 확인과 복구

제안과 취소는 배치를 저장하지 않습니다. 적용을 누르는 순간부터 결과 확인까지 가구 조작과 실행 취소 및 구조 저장과 파일 업로드 및 프로젝트 전환을 막습니다. 응답이 유실되면 취소로 편집을 재개하지 않고 같은 `proposalId`로 기존 확인 API를 다시 호출합니다. 서버는 이미 처리된 제안의 결과를 돌려주므로 명령을 다시 만들거나 중복 적용하지 않습니다. 서버의 409는 기존 충돌 복구로 연결합니다.

모델 요청은 중단할 수 있습니다. 중단과 프로젝트 전환 및 화면 종료 후 도착한 모델 응답은 서버에 보내지 않습니다. 모델이나 서버 요청이 실패하면 입력과 배치를 보존하고 원인을 안내합니다.

현재 #168 응답은 모호한 명령의 순번을 `reply`의 `N번째 명령`으로만 알려줍니다. 복합 요청의 후보 선택은 이 순번을 검사해 `selections`의 0부터 시작하는 키로 전달합니다. 순번을 확인할 수 없으면 임의의 명령을 선택하지 않고 한 가구씩 요청하도록 안내합니다. 응답에 명령 순번 필드를 추가하면 이 문구 의존을 제거할 수 있습니다.
