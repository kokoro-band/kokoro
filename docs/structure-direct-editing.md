# 구조 화면에서 크기와 위치 조절하기

구조 화면의 평면도에서 방의 가장자리를 끌어 크기를 바꾸고 문과 창문의 위치와 폭을 조절할 수 있습니다. 기존 이동 도구와 정보 패널을 확장한 기능입니다. 화면 구성과 시각 규칙은 [DESIGN.md](../DESIGN.md)의 SEED 체계를 따릅니다.

## 방 크기 조절

이동 도구에서 방을 선택하면 네 변의 가운데와 네 모서리에 조절점이 나타납니다. 변의 점은 한 방향의 길이를 바꾸고 모서리의 점은 가로와 세로를 함께 바꿉니다. 끄는 쪽의 반대편 경계는 제자리에 남습니다. 방 안을 끌면 기존처럼 방 전체를 옮깁니다.

가로와 세로는 각각 1m부터 40m까지 조절할 수 있으며 변경은 0.1m 단위로 맞춰집니다. ㄱ자 방도 바깥 사각형의 크기를 조절합니다. 깎인 모서리의 크기가 새 방 크기를 벗어나면 안쪽 부분을 남길 수 있는 크기로 제한합니다. 깎인 모서리를 조절하는 기존 점은 별도로 유지합니다.

방을 줄이거나 늘릴 때 기존 문과 창문은 실제 폭을 유지합니다. 조절한 방의 경계에 있는 문과 창문은 해당 변에서 중심이 차지하던 비율을 따라 이동합니다. 벽 끝에 걸리면 같은 폭을 유지하면서 벽 안으로 위치를 맞춥니다. 따라서 방 크기에 비례해 문과 창문 자체가 커지거나 작아지지는 않습니다.

다음 상황에서는 해당 크기 변경을 적용하지 않습니다.

- 변경한 벽이 기존 문이나 창문의 폭보다 짧습니다.
- 변경 후 문이나 창문이 속할 벽을 하나로 정할 수 없습니다.
- 보존하려는 문과 창문이 같은 벽에서 서로 겹칩니다.

끌고 있는 중에 위 조건을 만나면 마지막으로 유효했던 미리보기를 유지하고 화면 아래에 이유를 알립니다. 그 상태에서 놓으면 마지막 유효 크기가 확정됩니다. 조작 전체를 버리려면 놓기 전에 Escape를 누릅니다. 숫자 입력으로 시도한 크기를 적용할 수 없는 경우에는 입력 전 구조를 유지합니다.

다른 방과 겹치거나 떨어진 상태는 초안에서 확인할 수 있습니다. 다만 모든 방이 벽을 맞대고 연결되며 겹치지 않아야 구조를 저장할 수 있습니다. 이 저장 조건은 문과 창문을 보존할 수 없어 크기 변경 자체를 거절하는 조건과 별개입니다.

## 문과 창문 조절

이동 도구 또는 문과 창을 추가하는 도구에서 기존 문이나 창문을 선택합니다. 몸체를 끌면 폭을 유지한 채 벽을 따라 이동합니다. 선택 후 나타나는 양 끝의 점을 끌면 반대쪽 끝을 고정한 채 폭을 바꿉니다.

조절 범위는 현재 붙어 있는 벽 안으로 제한됩니다. 벽 끝이나 같은 벽의 다른 문과 창문에 닿으면 멈춥니다. 다른 문과 창문을 넘어 순서를 바꾸거나 다른 벽으로 옮길 수는 없습니다. 폭은 최소 0.3m이며 드래그의 이동량과 폭 변경량은 0.1m 단위로 맞춰집니다. 문과 창문의 종류와 ID는 유지됩니다.

## 키보드와 숫자 입력

드래그 없이도 같은 크기와 위치를 입력할 수 있습니다. 이동 도구에서 Tab으로 방에 접근한 뒤 Enter 또는 Space로 선택합니다. 문과 창문은 이동 도구와 문과 창을 추가하는 도구에서 같은 방식으로 선택할 수 있습니다. 선택만으로는 구조가 변경되지 않습니다.

| 선택한 대상 | 정보 패널의 입력 | 적용 방식 |
|---|---|---|
| 방 | 가로와 세로 | 왼쪽 위를 고정하고 오른쪽과 아래쪽으로 크기를 바꿉니다 |
| 문 또는 창문 | 벽 시작점에서 거리 | 현재 벽의 시작점부터 첫 번째 끝까지의 거리를 바꿉니다 |
| 문 또는 창문 | 폭 | 첫 번째 끝을 고정하고 두 번째 끝을 움직입니다 |

벽 시작점은 내부 도면 데이터의 방향을 따릅니다. 화면에서 항상 왼쪽이나 위쪽이라는 의미는 아닙니다. 입력 범위에는 같은 벽의 다른 문과 창문도 반영됩니다.

숫자를 적고 Enter를 누르거나 입력란을 벗어나면 확정됩니다. 방 크기는 소수 첫째 자리까지 입력합니다. 문과 창문의 거리와 폭은 소수 둘째 자리까지 입력하므로 드래그보다 세밀하게 맞출 수 있습니다. 위아래 화살표는 0.1m씩 바로 적용합니다. 입력란에서 Escape를 누르면 아직 확정하지 않은 입력을 버립니다. 빈 값이나 숫자가 아닌 값은 적용하지 않습니다. 방 크기 입력도 드래그와 같은 문과 창문 보존 검사를 거칩니다.

## 실행 취소와 조작 취소

한 번 끌고 놓은 변경은 실행 취소 기록 하나로 남습니다. 도구 모음의 실행 취소와 다시 실행을 사용하거나 기존 단축키를 사용할 수 있습니다. Mac에서는 Command를 사용하고 다른 환경에서는 Ctrl을 사용합니다. 실행 취소는 Z이며 다시 실행은 Shift+Z 또는 Y입니다.

드래그 중 Escape를 누르면 시작 전 구조로 돌아갑니다. 브라우저 창이 포커스를 잃거나 구조 화면이 비활성화되거나 포인터 조작이 취소된 경우에도 진행 중인 변경을 버립니다. 이 취소는 기존 실행 취소와 다시 실행 기록을 바꾸지 않습니다. 누른 뒤 거의 움직이지 않은 선택 동작도 변경 기록을 만들지 않습니다.

드래그 미리보기 동안에는 도구 모음과 정보 패널의 편집을 잠급니다. 구조 저장은 드래그가 끝나고 저장 조건을 만족할 때 가능합니다. 정보 패널의 되돌리기는 개별 조작의 실행 취소와 달리 편집을 시작할 때의 구조로 복원합니다.

## 기존 시각 규칙의 적용

선택한 방과 조절점에는 기존 SEED의 브랜드 색 역할을 사용합니다. 방의 기본 배경과 문과 창문의 표현도 기존 의미 기반 색상을 유지합니다. 숫자 입력은 기존 `MeterField`와 SEED `TextField`를 사용하며 안내 문장은 `Type`의 caption 역할을 따릅니다. 별도 색상 체계나 디자인 토큰을 추가하지 않습니다.

새 조절점은 보이는 점보다 넓은 지름 28 CSS px 영역에서 잡을 수 있습니다. 문과 창문의 몸체에는 두께 28 CSS px의 투명한 선택 영역이 있습니다. 평면도의 미터 좌표와 화면의 픽셀 크기를 환산하므로 큰 도면이나 좁은 화면에서도 이 영역의 화면 크기를 유지합니다. 이는 모든 기존 조작점에 적용되는 규칙은 아닙니다.

키보드로 선택할 수 있는 방과 문과 창문에는 포커스 표시가 있습니다. SVG 선을 별도로 그려 도면 배율과 무관하게 화면에서 두께 3px를 유지합니다. 820px 이하에서는 기존처럼 정보 패널이 평면도 아래로 이어지고 저장 버튼이 패널 아래에 붙습니다. 모바일 화면에서도 숫자 입력을 조작 대안으로 제공합니다.

## 구현 위치

| 파일 | 역할 |
|---|---|
| `frontend/src/features/studio/components/StructureView.tsx` | 선택과 조절점 표시와 숫자 입력을 연결합니다 |
| `frontend/src/features/studio/structure-editing.ts` | 방 크기와 문과 창문 위치를 계산하고 보존 가능 여부를 검사합니다 |
| `frontend/src/features/studio/hooks/useStructureDrag.ts` | 확정 전 미리보기를 관리하고 한 번의 드래그를 한 번의 변경으로 기록합니다 |
| `frontend/src/features/studio/hooks/usePlanScale.ts` | 화면 크기를 관찰해 조절점의 선택 영역을 미터 단위로 환산합니다 |
| `frontend/src/styles/structure.css` | 기존 SEED 색상과 선택 영역과 포커스 표시를 적용합니다 |

드래그 시작 시 화면 좌표를 도면 좌표로 바꾸는 기준과 보이는 도면 범위를 고정합니다. 이 덕분에 크기가 바뀌는 동안 화면의 자동 맞춤이 포인터 이동량에 다시 영향을 주지 않습니다. 놓을 때는 전체 도면의 시작 위치를 정리한 뒤 하나의 변경으로 확정합니다.

## 검증과 남은 범위

프론트엔드의 정적 검사와 테스트와 빌드는 `frontend/`에서 다음 명령으로 검증합니다. 이 검증은 브라우저에서 실제로 조작한 결과와 별도로 확인합니다.

```bash
vp check
vp test
vp run build
```

브라우저에서는 방 축소와 위쪽 확장을 확인했습니다. 실행 취소와 다시 실행도 확인했습니다. 문 이동과 창문 폭 변경을 확인했으며 다른 문이나 창문에 닿으면 더 움직이지 않는 동작과 기존 문과 창문이 보존되는 동작을 확인했습니다. 저장 후 새로고침과 배치 화면의 2D 및 3D 표시도 확인했습니다. 키보드 선택만으로 미저장 변경 상태가 되지 않는 점도 확인했습니다.

모바일은 좁은 화면의 캡처로 배치와 입력란을 확인했습니다. 실제 터치 기기에서 손가락으로 조절하는 검증은 아직 하지 않았습니다.

이 기능의 직접 조작 범위는 구조 화면의 2D 평면도입니다. 저장한 구조는 기존 배치 데이터 흐름을 따르지만 3D 화면이나 WebXR 안에서 방과 문과 창문을 직접 조절하는 기능은 추가하지 않습니다. 실제 WebXR 헤드셋 검증과 운영 배포 확인도 이 검증에 포함되지 않습니다.
