# WebXR 지원 범위와 제한 사항

웹 VR 모드는 별도 앱 없이 같은 프로젝트 화면에서 시작합니다. 이 문서는 어떤 기기와 브라우저에서 VR 모드를 지원하는지, 실제로 검증한 범위와 알려진 제한 사항을 정리합니다. 2026-10 기준이며 검증 범위가 바뀌면 함께 갱신합니다.

## 지원 범위

| 구분 | 기기 | 브라우저 | 상태 |
|---|---|---|---|
| 공식 지원 | Meta Quest 3 | Meta Quest Browser | 검증 완료 |
| 동작 예상 | Meta Quest 2, 3S, Pro | Meta Quest Browser | 미검증 |
| 동작 예상 | PC VR (Quest Link/Air Link, SteamVR 헤드셋) | Windows Chrome, Edge | 미검증. 활성 OpenXR 런타임 설정 필요 |
| 동작 예상 | Samsung Galaxy XR | Chrome | 미검증 |
| 미지원 | Apple Vision Pro | Safari | WebXR은 되지만 컨트롤러가 없어 이 앱의 입력 방식과 맞지 않음 |
| 미지원 | PICO | 기본 브라우저 | 기본 브라우저의 WebXR 지원이 불안정 |
| 미지원 | iPhone, iPad, Mac | Safari | WebXR 없음 |
| 미지원 | 모든 기기 | Firefox | WebXR 없음 |
| 대체 흐름 | 헤드셋 없는 PC | Chrome, Edge | VR 버튼 비활성. 2D와 3D 보기 사용 |

VR을 지원하지 않는 환경에서도 2D와 3D 보기의 편집 흐름은 그대로 사용할 수 있어야 합니다.

## 검증 기록

| 날짜 | 기기 | 브라우저 | 확인한 내용 |
|---|---|---|---|
| 2026-09-18 | Meta Quest 3 | Meta Quest Browser | VR 진입과 종료, 실제 스케일, 텔레포트, 스틱 이동, 스냅 턴, 벽 충돌, 문 열림 |
| 2026-09-20 | Meta Quest 3 | Meta Quest Browser | GLB 가구 모델 표시, 컨트롤러로 가구 잡기와 이동 |
| 2026-10-06 | Meta Quest 3 | Meta Quest Browser | 가구 잡기와 이동 및 회전, 놓은 뒤 저장과 새로고침 후 유지, 잡은 채 종료 시 되돌리기, 트리거로 문 열고 닫기, 잡은 채 이동할 때 끊김 없음 |

검증은 USB 연결과 `adb reverse`로 로컬 개발 서버에 접속해 진행했습니다. 공개 HTTPS 주소에서의 검증은 아직 없습니다.

VR 진입과 종료 3회 반복, ㄱ자 방, GLB 로딩 실패, 지원하지 않는 브라우저와 권한 거부 안내는 아직 헤드셋에서 기록하지 않았습니다. 확인하면 위 표에 추가합니다.

## 세션 시작 조건

- WebXR은 HTTPS에서만 동작합니다. `localhost`는 예외입니다.
- 몰입형 세션은 사용자 클릭 안에서만 시작할 수 있습니다. 화면의 VR 진입 버튼이 이 역할을 합니다.
- Meta Quest에서는 가디언(플레이 영역)이 설정되어 있어야 바닥 기준 좌표를 얻을 수 있습니다.
- 양손 컨트롤러가 켜져 있어야 합니다. 손 추적만으로는 이동할 수 없습니다.

## 조작

| 입력 | 동작 |
|---|---|
| 왼쪽 스틱 | 머리가 향한 방향으로 이동 |
| 오른쪽 스틱 좌우 | 30도 스냅 턴 |
| 트리거 (바닥을 가리킨 상태) | 바닥 표시 지점으로 텔레포트 |
| 트리거 (문을 가리킨 상태) | 문을 열거나 닫습니다 |
| 그립 또는 트리거 (가구를 가리킨 상태) | 가구 잡기. 잡는 동안 레이저가 주황색으로 바뀝니다 |
| 잡은 채 레이저를 바닥으로 | 레이저가 움직인 거리의 0.6배만큼 부드럽게 따라옵니다. 벽은 통과하지 못하고 벽에 가까우면 붙습니다 |
| 잡은 손의 스틱 좌우 | 가구를 15도씩 회전. 오른쪽이 시계 방향이며 계속 밀면 반복합니다. 벽에 막히면 그 각도에서 멈춥니다 |
| 잡은 버튼을 뗌 | 그 자리에 배치하고 위치와 방향을 한 번에 저장합니다. 실행 취소 한 번으로 되돌립니다 |
| 잡은 채 VR을 나가거나 컨트롤러가 끊김 | 잡기를 취소하고 가구를 잡기 전 자리로 되돌립니다 |

잡을 때와 놓을 때, 회전 한 칸마다 컨트롤러가 짧게 진동합니다. 가구를 잡은 손의 스틱은 회전에만 쓰이고, 다른 손의 스틱은 평소처럼 이동이나 스냅 턴을 합니다. 오른손으로 회전하다 놓았다면 스틱을 가운데로 돌린 뒤에 스냅 턴이 다시 됩니다.

벽과 창은 통과할 수 없습니다. 직접 열고 닫지 않은 문은 다가가면 열리고, 2D와 3D나 VR에서 닫아 둔 문은 다시 열 때까지 지나갈 수 없습니다. 집 외곽 밖으로는 이동할 수 없습니다.

## 알려진 제한 사항

### 입력

- 트리거로도 가구를 잡을 수 있어서, 가구를 가리킨 채 트리거를 누르면 텔레포트 대신 가구를 잡습니다. 그립으로 잡으면 두 동작이 겹치지 않습니다.
- 가구를 든 손으로는 걷거나 몸을 돌릴 수 없습니다. 다른 손으로 이동합니다.
- 잡은 가구는 레이저보다 덜 움직여서 오래 옮기면 레이저 끝에서 멀어집니다. 멀리 옮길 때는 놓고 다가가서 다시 잡습니다.
- 배치 화면에서 방 하나에 초점을 둔 채 VR에 들어가면 그 방 중심에서 시작하고 가구도 그 방 밖으로 옮길 수 없습니다.
- 한 번에 가구 하나만 잡을 수 있습니다.
- 스틱 축은 Meta Quest 컨트롤러 기준입니다. 다른 컨트롤러 프로파일은 검증하지 않았습니다.
- 손 추적, 시선과 핀치 입력은 지원하지 않습니다.
- VR 안에서는 가구 추가와 삭제, 카탈로그, 어시스턴트 UI를 사용할 수 없습니다. 웹 화면에서 배치한 뒤 VR에서 확인하고 위치와 방향을 조정하는 흐름을 전제로 합니다.

### 문

- 직접 열고 닫지 않은 문은 다가가는 사람의 반대쪽으로 열립니다. 도면에 그린 방향과 다를 수 있습니다.
- 폭이 60cm보다 좁은 문은 열려 있어도 지나갈 수 없습니다.
- 문을 열고 닫은 상태는 저장되지 않아서 새로고침하면 모두 닫힙니다.

### 표시

- 방 이름 라벨이 벽 너머로도 보입니다.
- 천장은 VR 모드에서만 표시됩니다.

### 성능과 편의

- 브라우저 VR은 네이티브 앱보다 느립니다. Quest 3는 90fps, Quest 2는 72fps가 목표이며 아직 프레임을 측정하지 않았습니다.
- Meta Quest Browser는 데스크톱보다 WebGL 텍스처와 프레임버퍼 최대 크기가 작습니다. 큰 텍스처를 쓰는 가구 모델은 로딩과 메모리를 확인해야 합니다.
- 스틱 이동 중 멀미가 보고되었습니다. 이동 중 시야 가장자리를 어둡게 하는 처리와 속도 조정을 검토 중입니다.

## 개발과 디버깅

### 로컬 개발 서버를 Quest에서 열기

1. Quest 개발자 모드를 켜고 USB로 PC에 연결합니다.
2. 개발 서버를 IPv4로 엽니다. 기본 설정은 IPv6에만 열려 `adb reverse`가 연결되지 않습니다.

   ```bash
   cd frontend
   vp dev --host 127.0.0.1
   ```

3. 포트를 헤드셋으로 연결합니다.

   ```bash
   adb reverse tcp:5173 tcp:5173
   ```

4. Quest 브라우저에서 `http://localhost:5173`을 엽니다. `localhost`는 HTTPS 없이 WebXR을 허용합니다.

### Quest 브라우저 원격 디버깅

PC Chrome에서 `chrome://inspect/#devices`를 열면 USB로 연결된 Quest 브라우저 탭이 보입니다. `inspect`를 누르면 헤드셋에서 실행 중인 페이지의 Console과 Network와 디버거를 PC에서 사용할 수 있습니다.

### 헤드셋 없이 확인하기

Chrome 확장 Immersive Web Emulator를 설치하면 데스크톱에서 세션 진입과 컨트롤러 입력을 흉내 낼 수 있습니다. 실제 성능과 스케일 감각은 반영되지 않으므로 최종 확인은 헤드셋에서 합니다.

### PC VR로 확인하기

Quest Link 또는 SteamVR을 활성 OpenXR 런타임으로 두면 Windows Chrome에서 페이지를 열어 VR로 진입할 수 있습니다. PC GPU로 렌더링하며 PC의 DevTools를 그대로 사용할 수 있어 디버깅에 유리합니다.
