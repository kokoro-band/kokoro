# 프론트엔드

도면과 가구 카탈로그와 2D 편집과 Three.js 3D 미리보기와 WebXR VR을 모두 제공하는 React 웹 애플리케이션입니다. VR용 별도 앱은 사용하지 않습니다.

프론트엔드 도구는 Vite+로 관리합니다.

```bash
vp install
vp dev
```

기본값은 서버 없이 사용할 수 있는 로컬 데모입니다. `VITE_API_MODE=server`와 `VITE_API_BASE_URL=http://localhost:8080/api`를 설정하면 Spring 서버에 연결됩니다.

검증은 아래 명령으로 실행합니다.

```bash
vp check
vp test
vp run build
```

WebXR은 지원 기기에서 별도로 확인해야 합니다.

## 가구와 문 조작

가구를 끌거나 방향키로 옮길 때는 가구 전체 크기와 회전 방향을 기준으로 벽 앞에서 멈춥니다. 좌표를 직접 입력해도 같은 규칙을 적용합니다. 벽 쪽으로 움직이다가 10cm 안으로 가까워지면 벽면에 맞춰 붙습니다. 벽에 닿은 채로 끌면 벽을 따라 이동하며 회전 중 벽에 닿으면 회전도 멈춥니다.

기존 도면에 잘못 놓인 가구가 있어도 편집을 시작할 수 있습니다. 해당 가구를 조작할 때 들어갈 수 있는 위치로 보정합니다. 가구를 추가할 때도 벽과 겹치지 않는 위치를 찾으며 공간이 없으면 추가하지 않고 안내합니다. 가구끼리 겹치거나 문 앞을 가리는 문제는 경고로 표시합니다.

선택 도구인 `1`이나 이동 도구인 `2`에서 문짝을 누르면 문이 열리거나 닫힙니다. 상단의 `문` 메뉴는 키보드로도 조작할 수 있습니다. 화면 이동 도구인 `3`에서는 문을 눌러도 상태가 바뀌지 않습니다. 열림 상태는 2D와 3D를 바꿔도 유지되지만 저장 대상은 아니므로 편집 화면을 나가거나 새로고침하면 초기화됩니다.

VR에서는 직접 조작하지 않은 문이 가까이 다가가면 열립니다. 직접 닫은 문은 다시 열어야 하며 문이 충분히 열려야 통과할 수 있습니다. 이 동작은 자동 테스트로 검증했으며 실제 헤드셋 검증은 별도로 필요합니다. 가구 이동에서는 문이 열린 곳도 벽 구간으로 취급하므로 다른 방에 놓으려면 해당 방에서 가구를 추가해야 합니다.

2026년 9월 28일 최신 main 기반 통합에서 기본 경로와 `/kokoro/` 경로의 테스트 232개 및 정적 검사와 빌드를 통과했습니다. 브라우저에서 벽을 넘어서는 드래그와 큰 좌표 입력 제한 및 문짝 클릭과 키보드 메뉴 조작을 확인했습니다. 수동 문은 처음에는 닫혀 있고 열면 구조 도면이 표시한 방향으로 움직입니다. 공개 배포와 실제 헤드셋 검증은 이 결과에 포함하지 않습니다.

도면 이미지는 공간 편집기의 초안 생성에서 분석합니다. PDF 파일 업로드의 서버 상태가 READY여도 이미지 분석 결과가 생기는 것은 아닙니다. 지원 이미지 형식과 보정 안내는 화면에 표시합니다.

모델 파일을 불러오지 못하면 대체 모델로 표시됩니다. 서버 연결 오류가 나면 Spring과 PostgreSQL의 실행 상태 및 `VITE_API_BASE_URL`을 확인합니다. 환경 변수 변경 후 개발 서버를 다시 실행해야 합니다. 실제 기기 기록은 [이슈 #6](https://github.com/kokoro-band/kokoro/issues/6)에서 관리합니다.
